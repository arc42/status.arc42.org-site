=== Availability Monitoring

Availability probing is triggered externally by `cron-job.org` calling `POST /api/probe` on a 15-minute schedule with a Bearer authentication token (see ADR-0019 for details).

The API Gateway dispatches the request to `internal/probe`, which measures all monitored properties concurrently, performs 2-of-3 failure confirmations, records results in Turso, and alerts Slack if any site is `down`.

`internal/availability` is the read/write and computation layer: `internal/probe` writes transitions, daily rollups, and heartbeats through it, and `internal/api` reads it to compute the status tokens, verdict, and 30-day history shown on the pages.

Runtime storage uses three Turso tables:
- `status_snapshot` — state transitions (`site`, `status`, `changed_at`, `response_ms`, `detail`, `monitor_id` as `vantage`).
- `status_bucket` — daily downtime rollups per site (`site`, `bucket_start`, `bucket_kind='day'`, `downtime_minutes`, `outage_count`).
- `probe_run` — run heartbeat log (`run_at`, `vantage`, `sites_checked`, `duration_ms`).
